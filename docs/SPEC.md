# SPEC.md — 舞台公演 興行設計シミュレーター

## 1. プロダクトの目的

本ツールは「AIが適正価格を断定するサービス」ではない。演劇・コント・劇団・お笑いユニット等の主催者が、
チケット価格 × 会場キャパシティ × 公演回数 × 立地 × 過去実績 を組み合わせて、
**「どの興行設計が自分たちに適しているか」を比較検討するための意思決定支援ツール**である。

目的（満席重視 / 売上重視 / 利益重視 / 新規客獲得 / ブランド価格維持）によって
「正しい答え」が変わることを前提に設計する。単一の最適解を返さない。

## 2. 非機能要件

- LLM（OpenAI/Claude/Gemini等）には一切接続しない。MVPは deterministic なルールベース計算のみ。
- 需要予測コンポーネント（`DemandEstimator`）のみを将来 ML モデルに差し替えられるよう、
  計算ロジックとシミュレーションを明確に分離する（詳細: `ARCHITECTURE.md`）。
- 公開Webサービスを想定したセキュリティ対策を行う（詳細: `README.md` セキュリティ節）。

## 3. 入力仕様

### A. 団体情報
団体名 / ジャンル（演劇・コント・その他） / 活動年数 / X・Instagram・YouTube・その他SNSフォロワー数。
SNSは補助情報。過大評価しない（`CALCULATION_LOGIC.md` 9章）。

### B. 過去公演（最低1件、推奨3〜5件）
公演名 / 開催日 / 都道府県 / エリア / 会場名 / キャパ / チケット価格 / 公演回数 / 販売枚数 /
完売有無 / 完売した場合の完売日数前 / 新作・再演 / 平日・土日祝 / 昼・夜。
直近の公演ほど基礎集客力の推定に強く反映する（指数減衰、`CALCULATION_LOGIC.md` 7章）。

### C. 今回の公演
開催地域 / 新作・再演 / 公演日 / 公演回数候補（複数可） / 平日・土日祝 / 昼・夜 / 希少性 /
ゲスト有無 / 特別公演か / 希望価格下限・上限。

### D. 候補会場（複数登録可）
会場名 / 地域 / キャパ / 会場費 / 駅徒歩分数 / 立地評価 / 会場ブランド評価。
MVPでは会場DBの自動取得は行わず、ユーザー入力とする。

## 4. 出力仕様

- 推奨価格帯（例: 3,800〜4,500円）
- バランス価格
- 満席重視価格（目標稼働率 90〜100%）
- 売上重視価格（price × expected_sales 最大化）
- 利益重視価格（ticket_revenue - venue_cost 最大化）
- シナリオ比較表（会場 × 価格 × 公演回数、価格は100円刻みで探索）
- 価格—動員グラフ、価格—売上グラフ
- Venue Fit 判定（小さすぎる/適切/やや大きい/大きすぎる）とリスク警告
- 説明可能性セクション（推定の内訳を可視化、ブラックボックス化しない）
- 免責文言（`README.md` 免責節と同一）

## 5. 避けるべきこと（最重要原則）

1. フォロワー数が多いから動員できると単純判断しない。
2. 完売枚数を真の需要と同一視しない（censored data として扱う）。
3. 高価格公演の動員が多い実績から「値上げすると客が増える」と学習しない（内生性の排除）。
4. 最大売上だけを理由に巨大会場を推奨しない。
5. 根拠が説明できない数値を提示しない。
6. ML/AIの使用自体を目的化しない。

このMVPの目的は精密な未来予測ではなく、主催者が価格・客席数・会場・公演数のトレードオフを
合理的に検討できるようにすることである。
